CLI guide

Tools 1.1.0 candidate supports Linux/macOS and Python 3.12–3.14.

01

Install and first check

Shell commands
python -m pip install 'golded-ftn-tools[network]==1.1.0'
ftnt --version
ftnt catalog

Before publication, install the reviewed candidate wheels together. The network extra supplies packet, nodelist, binkp and tosser dependencies. Without it, base commands continue to work and network commands report network_missing.

02

Message bases

Shell commands
ftnt create ./demo --format jam
ftnt write ./demo --format jam < message.json
ftnt heads ./demo --format jam
ftnt read ./demo 1 --format jam --body
ftnt export ./demo --format jam

Use the command's --help for input schemas and flags. write accepts a JSON object with from_name, to_name, subject and body_text; --jsonl appends each message separately. A later failure does not undo prior commits. A closed output pipe may hide a committed receipt; replaying the input can duplicate messages. MSG requires explicit FTSC or Opus format; Hudson requires a board. Keep bases offline for CLI mutations.

03

Packets and lists

Shell commands
ftnt packet read mail.pkt
ftnt packet write --output mail.pkt < packet.json
ftnt nodelist parse NODELIST.XXX --domain test.invalid --default-zone 2
ftnt nodelist lookup NODELIST.XXX --domain test.invalid --address 2:999/1

These are commands, not fixture production addresses. Packet read validates framing and semantic fields. Nodelist parsing is not route configuration. See the package references for schemas, CRC policy and supported dialects.

04

Node operations

Shell commands
ftnt node --config node.toml check
ftnt node --config node.toml recover
ftnt node --config node.toml toss
ftnt node --config node.toml scan
ftnt node --config node.toml status
ftnt node --config node.toml poll --help
ftnt node --config node.toml serve --help

Read Tosser operations before creating node.toml. Keep credentials in protected configuration, never arguments. poll/serve accept loopback hosts only. recover reconciles journal/base work; status exposes queues and HELD. An empty transport spool does not prove successful import into a recipient mailbox.

05

Output and errors

Operational errors print closed codes without paths, payloads, credentials or a traceback, including --debug. Exit codes are documented by the command help; archive recovery exits 7 when issues occur, broken stdout exits 141. Read stdout as data and stderr as diagnostics. --log-level overrides TOML [logging].level; OFF suppresses logs, not the journal. repair is an explicit text heuristic; readers and exporters never repair silently. MCP retains only catalog/heads/read/export/ decode/repair and exposes no node or writer commands.
