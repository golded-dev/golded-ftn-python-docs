Local bases. Explicit routes.

golded-ftn-tosser

A tosser sorts incoming FTN messages into local message bases and prepares outgoing messages for delivery. It brings together message storage, packet files, routing rules and file transfer. Use it when you want to operate a node, meaning a configured system that exchanges mail with other systems. To read an archive or try one local message, begin with the library guide instead.

Version 1.0.0. Python 3.12–3.14 on Linux and macOS.

01

Installation

Shell commands
python -m pip install golded-ftn-tosser==1.0.0

The package is published on PyPI. The command above installs the reviewed release; no sibling checkout or private wheelhouse is needed.

02

First working example

This first example only creates a local node with no peers, routes or message areas and checks its state. It does not send or receive mail. The later sections explain the configuration needed for delivery.

Python · RUNNABLE
from pathlib import Path
from tempfile import TemporaryDirectory
from golded_ftn_tosser import TosserNode

with TemporaryDirectory() as directory:
    root = Path(directory)
    config: dict[str, object] = {
        "product_id": 0x00FE,  # Synthetic fixture only.
        "paths": {
            name: str(root / name)
            for name in ("state", "inbound", "outbound", "held", "receipts")
        },
        "domains": [{"name": "test.invalid", "default_zone": 2}],
        "akas": [{"address": "2:999/1@test.invalid"}],
        "links": [],
        "areas": [],
        "area_rights": [],
        "mailboxes": [],
        "routes": [],
    }
    node = TosserNode.from_mapping(config)
    assert node.check()["ok"] is True
    node.recover()
    assert node.status()["held_reasons"] == []
03

Configuration and credentials

TosserNode.from_path loads strict TOML; unknown keys fail closed. The root table requires product_id; optional charset_fallback defaults to CP850 and lock_timeout controls lock acquisition. [paths] contains state, inbound, secure_inbound, outbound, held and receipts. Domain, AKA, link, area, rights, mailbox and route tables define the node. The no-link example above is a local journal smoke test, not a usable network.

Use [[domains]] name/default_zone, [[akas]] address, and [[links]] address, session_password, areafix_password, host, port and optional allow_plaintext. Session and AreaFix passwords have different purposes. Store them only in protected TOML (mode 0600) or build an in-memory mapping from a secret store. Never pass credentials in argv, examples, logs or issue reports. Fixtures use test.invalid, loopback peers and product_id 0x00FE; none are production assignments or deployment defaults.

[[areas]] requires domain/tag/format/path/kind (echo or netmail). Hudson additionally needs board 1–200 and the correct scan_dir. Squish needs an explicit IANA timezone when converting naive times. [[area_rights]] controls import/export per domain, tag and link. [[mailboxes]] maps a full destination address to domain/area_tag; [[routes]] maps destination to via. No route is invented from a nodelist.

04

Import, scan, routing and transport

Call check, then recover before resuming normal work. toss validates complete packets and authenticated receipts before record import, routes netmail only to an explicit mailbox or route, and fans out echomail only to permitted links. It preserves canonical imported packet bytes for forwarding. ZIP import is bounded against traversal, entry count, expansion and compression ratio; other archives are unsupported. scan assigns stable MSGIDs, records local changes and publishes durable outbound jobs. Direct read/write through format APIs does not perform this network policy.

poll delivers queued BSO work to a configured peer; serve receives binkp traffic. CLI wrappers refuse non-loopback hosts. Delivery receipts precede spool acknowledgement. The API exposes transport primitives; do not infer a hardened public service from a loopback integration test. AreaFix uses a separate password and stored subscriptions; RESCAN generations must not accidentally suppress requested replay as duplicates.

05

Queues, HELD and restart

Unknown netmail routes remain in the queue with unknown_route; there is no open relay. HELD records retain the original payload and a closed reason code. Inspect the reason, correct configuration or source data and deliberately reprocess; a successful command exit is not proof that every record reached a mailbox. status reports journal counts and held_reasons without exposing message contents.

Recovery follows INTENT → READY → DONE and format PREPARED/APPLIED/settled state. Call recover after restart, under the same state directory and base identity. COMMITTED finalizes, UNCOMMITTED rolls back, UNKNOWN remains unresolved. Never treat an uncertain commit as a safe resend or delete its recovery evidence. Preserve the journal, recovery directories, receipts, HELD and outbound payloads together.

06

Safety and concurrency

No TLS/CRYPT, fileecho, Type 2.2, public service hardening or live-network acceptance is promised. Format writer defaults remain offline. concurrent=True is only for the pinned Linux/macOS GoldED 3.1.0 profile described in the writer guide; it is not a promise for every editor/build/filesystem. The journal and routing locks impose an order; do not enter transport while holding a message-base mutation lock. Logging levels are OFF/ERROR/WARNING/INFO/DEBUG; OFF does not turn off the durable journal.
